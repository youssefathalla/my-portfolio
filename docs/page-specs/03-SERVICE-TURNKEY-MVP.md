   - Responsive layouts built with Tailwind CSS across mobile, tablet, and desktop breakpoints.
   - WCAG 2.2 AA accessibility compliance built in from the first component, not retrofitted at the end.

2. **Serverless Backend and Database (`<h3>`)**:
   - Authentication, database schema design, and serverless business logic, backed by security rules that block unauthorized access.
   - Non-Firebase backend support: ASP.NET, Node.js, and Java supported through REST or GraphQL APIs.
   - Unit and integration test suites covering business logic, state stores, and data utilities before every deployment.
   - Fair-play change policy: scope adjustments before feature development are free; new out-of-scope features quoted as mini-sprints.

3. **API Integration & Cloud Services (`<h3>`)**:
   - Seamless REST and GraphQL API integrations with robust error handling and typed models.
   - Real-time synchronization and data pipelines connecting cloud platforms and databases.
   - High-performance caching, optimistic UI updates, and instant perceived responsiveness.

4. **Bilingual English and Arabic Delivery (`<h3>`)**:
   - Native English (LTR) and Arabic (RTL) delivery with instant runtime switching.
   - Bi-directional layout system using logical CSS properties (`ms-`, `me-`, `ps-`, `pe-`).

### 4.5 Frequently Asked Questions (FAQ)

1. **Who owns the code after the project is complete?**
   - _Answer_: You do. On receipt of the final payment installment, the full source code, repository access, and deployment credentials transfer to you.
2. **What if my project doesn't run on Firebase?**
   - _Answer_: That's fine. While Firebase is the default recommendation for a fast serverless setup, the front-end integrates just as cleanly with an existing ASP.NET, Node.js, or Java backend over REST or GraphQL.
3. **What happens if I want to change scope mid-project?**
   - _Answer_: Requirements can be changed freely before development starts on a feature. Once work is underway on that feature, changes are handled under the change policy published on the policies page.
4. **What happens after the warranty period ends?**
   - _Answer_: You can manage the application independently, or continue with one of the ongoing care plans for regular updates and dedicated hours, details of which are also published on the policies page.
5. **How long does a typical build take?**
   - _Answer_: Most fixed-price builds ship in 4-6 weeks from kickoff to launch, depending on scope.
